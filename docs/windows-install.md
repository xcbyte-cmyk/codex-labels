# Windows PC별 설치와 업데이트

배포 ZIP에는 라벨 준비 도구, 명령 파일, 안내 및 Python/PyInstaller 라이선스만 들어 있다. 공식 Codex, 개인 labels.json·assignments.json, 로그인 프로필과 로그는 포함하지 않는다. GitHub Actions에서 빌드한 ZIP과 SHA256SUMS.txt를 릴리즈에 게시한다.

## 사용 순서

1. Windows x64 PC에 공식 Codex를 설치한다. 특정 버전으로 제한하지 않고, 등록된 설치본 중 Labels가 연결할 구조가 있는 가장 새 버전을 사용한다. 마지막으로 실행을 확인한 버전은 내부 앱 26.917.51856이다. 이 변경을 포함한 ZIP은 아직 발행하지 않았으므로 현재는 README의 소스 설치 절차를 사용한다(기존 v0.3.3 ZIP은 26.915 전용). 연결 구조가 없는 버전은 패치하지 않는다.

v0.3.0부터 helper의 기본 실행 및 `launch`는 실행본 준비 후 공통 계정 선택기를 연다. `accounts`도 같은 준비·선택 경로를 사용한다. 기존 기본 프로필은 선택기의 **기본 프로필 열기** 또는 `launch-direct`로 실행한다. 계정 자료는 `%LOCALAPPDATA%\CodexLabels\AccountWindows`에 유지하며, 이전 설치 폴더의 계정 자료는 자동 이전하지 않는다. 창의 준비 완료 후 선택기가 닫힌다. 업데이트의 `launch --wait-pid` 재시작은 기본 프로필 직접 실행을 유지한다.
2. ZIP을 계속 사용할 쓰기 가능한 폴더에 모두 푼다. `D:\Apps\CodexLabels` 같은 폴더를 권장한다. ZIP 안에서 실행하거나 준비된 runtime 폴더를 다른 PC에 복사하지 않는다.
3. 설치.cmd를 실행한다. 현재 사용자에게 등록된 공식 설치 경로를 조회하고 원본을 수정하지 않는 앱 사본을 만든다. Python·Git·Node.js를 추가 설치할 필요가 없다.
4. 바탕화면 Codex Labels 또는 실행.cmd를 사용한다. 계정 로그인은 해당 PC에서 한다.

설치본은 약 2GB이며 설치 시 약 3GB 여유 공간이 필요하다. 업데이트 백업을 포함하면 더 많은 공간을 사용한다. 동일 폴더에서 설치를 동시에 진행할 수 없으며, 해당 실행본이 켜져 있으면 종료를 안내하고 중단한다. 앱을 강제로 종료하지 않는다.

## 설정과 업데이트

v0.2.4부터 정상 실행본이 있으면 그 Codex 기반을 유지하며 Labels 코드를 갱신한다. 공식 Codex가 더 새 버전으로 바뀌어도 기존 기반의 Labels 업데이트는 가능하다. 현재 지원 구조를 벗어난 패치본은 갱신하지 않는다. 새 Codex 기반 지원이나 모든 구버전 지원을 뜻하지 않는다.

새 실행본은 개인 계정·설정·대화를 복사하지 않은 임시 환경에서 Electron과 라벨 연결을 검사한 뒤 교체한다. 직전 실행본과 실행 도구를 보관하며, 새 앱이 종료되거나 실행에 실패하면 이전 버전으로 복구한다. 새 앱이 살아 있지만 준비 보고가 오지 않으면 강제 종료하지 않고, 닫고 다시 실행했을 때 복구한다. 정상 업데이트 후에도 설정의 **이전 버전으로 돌아가기**를 사용할 수 있다. 복구는 실행 파일에만 적용되며 labels.json·assignments.json과 사용자 프로필을 되돌리지 않는다. 이 버전에서는 데이터 형식을 변경하지 않는다.

시작 시 원본 설치 버전을 로컬에서 한 번 확인한다. Labels 기반 버전과 다르면 설정창 업데이트 영역에 버전 차이를 표시한다. 다음 Labels 실행 때 새 원본으로 실행본을 다시 만들고 격리 검사·첫 실행 확인을 거쳐 전환한다. 실패하면 기존 실행본을 유지하고 같은 원본 빌드로는 재시도하지 않는다. 전환이 확인되면 직전 실행본 하나만 남기고 오래된 `runtime/app.backup-*`를 정리한다. Labels 업데이트 확인 버튼은 기존 공개 릴리스 조회만 수행하며 자동 다운로드·자동 패치·자동 재시작은 하지 않는다. 조회 실패는 앱 실행을 막지 않고, 다음 Labels 실행 시 다시 감지한다. 이미 설치된 원본만 비교하므로 Microsoft Store에만 올라온 새 버전은 감지 대상이 아니다.

이름·색상은 설치 폴더의 labels.json, 작업별 상태는 assignments.json에 저장한다. 다른 PC로 색상 설정을 옮기려면 Labels를 닫고 labels.json만 복사한다. 작업별 할당은 실제 host/kind/thread ID와 프로젝트 경로에 묶여 있으므로 다른 PC의 작업에 자동으로 맞춰지지 않는다. 자동 동기화는 없다.

v0.2.3부터 라벨 설정을 열면 항상 펼쳐진 Codex Labels 업데이트 영역에서 로컬 설치 상태를 읽고 GitHub 공개 최신 버전을 자동 조회한다. **업데이트 확인** 버튼으로 다시 조회할 수도 있다. 이미 다운로드한 업데이트가 설치 대기 중이면 추가 조회 없이 해당 상태를 먼저 표시한다. 현재 실행 버전과 최근 확인한 공개 버전을 구분하며, 조회 중과 조회 실패를 업데이트 없음으로 표시하지 않는다. 성공한 조회 정보는 앱 실행 중 로컬 상태 조회에도 유지한다.

다운로드와 설치는 사용자가 버튼을 눌렀을 때만 진행한다. 다운로드 완료 뒤 **설치하고 다시 실행**을 누르면 별도 진행 창이 현재 Labels의 정상 종료를 기다려 설치하고 앱을 다시 연다. 열린 작업이 중단될 수 있다는 안내를 보여주며, 저장하지 않은 라벨 편집은 먼저 저장·취소해야 한다. 강제 프로세스 종료는 하지 않는다. 설치 도구가 준비되지 않으면 기존 앱을 종료하지 않는다. 같은 버전·이전 버전·시험판은 자동 설치 대상이 아니다.

업데이트는 고정된 xcbyte-cmyk/codex-labels의 GitHub 정식 릴리스만 조회한다. GitHub API의 SHA-256 digest와 다운로드 길이를 확인하고 ZIP 파일 허용 목록과 패키지 버전을 검사한다. 구조를 감지하는 패키지(`appVersionPolicy: detect`)는 설치된 Codex 버전과 무관하게 받으며, 이전 패키지는 기존처럼 설치된 버전과 일치해야 한다. 개인 설정·할당·프로필과 공식 Codex는 업데이트 파일 목록에 포함되지 않는다. 네트워크/호환성/검증 실패는 현재 설치를 바꾸지 않는다. 실행 도구 교체 실패 시 이전 파일을 복원한다. `.updates/stage-*/previous`에 직전 실행 도구와 메타데이터를 보관한다.

설치 시 기존 runtime/app은 그대로 둔 채 새 사본을 완성하고 검증한다. 마지막 교체 단계에서만 이전 앱을 runtime/app.backup-날짜-식별자로 옮긴다. 설치 도중 중단되면 기존 앱이 유지되고, 짧은 교체 도중 중단되어 app이 사라진 경우 다음 실행에서 configPath와 ASAR 해시가 일치하는 백업을 복원한다. 복사 도중 알림 등으로 기존 앱이 다시 실행되면 교체하지 않는다. 새 설치가 실패해도 검증된 이전 앱은 열 수 있다. 진행 창은 새 실행 토큰 또는 새 프로세스의 최신 renderer 준비 보고를 확인해야 완료로 표시한다. 실행 실패 시 재시도 버튼과 오류를 표시하고 launch-error.json에 로컬 진단을 남긴다.

v0.1.0에서 최초 업그레이드하거나 수동 업데이트할 때는 새 ZIP을 기존 폴더에 풀고 설치.cmd를 다시 실행한다. labels.json과 assignments.json을 덮어쓰지 않는다. 준비된 앱을 다른 폴더로 옮긴 경우에도 설치.cmd를 다시 실행한다. 업데이트가 표시되려면 새로운 버전 번호로 GitHub 정식 릴리스와 Windows ZIP을 게시해야 한다. 브랜치 push만으로는 업데이트가 배포되지 않는다.

바탕화면에 다른 경로를 가리키는 같은 이름의 바로가기가 있으면 덮어쓰지 않는다. 이 경우 설치한 폴더의 실행.cmd를 사용할 수 있다. 기존 바로가기를 정리한 뒤 설치.cmd를 다시 실행하면 새 바로가기를 만들 수 있다.

프로필은 `%LOCALAPPDATA%\CodexLabels\User Data`이다. 원본 Codex와 CODEX_HOME 및 작업 저장소는 공유한다. 다른 Labels 사본이 이 프로필을 쓰는 동안 새 사본이 잘못 활성화되지 않도록 런처에서 확인한다. 원본 Codex는 종료할 필요가 없다. 알림 프로토콜은 자동 등록하지 않는다.

## 배포 패키지 빌드

Windows x64의 Python 3.11 이상에서:

```powershell
python -m pip install -r packaging/requirements-build.txt
python package_windows.py
$env:CODEX_LABELS_PACKAGE_ZIP = (Get-ChildItem dist/Codex-Labels-*-windows-x64.zip).FullName
python -m unittest discover -s tests -p test_windows_package.py -v
```

PyInstaller의 onefile 및 add-data 기능으로 Python 런타임과 필요한 확장 파일만 포함한다. 번들 내부 파일과 배포 EXE의 위치를 구분한다. [공식 패키징 옵션](https://pyinstaller.org/en/stable/usage.html), [공식 런타임 경로 안내](https://pyinstaller.org/en/stable/runtime-information.html)를 따른다.

ZIP 파일 목록은 코드의 허용 목록으로 제한한다. CI는 실제로 빌드된 EXE를 한글 경로에 풀어 합성 Codex 설치본 준비·재설치·설정 보존·검사와 임시 바로가기 소유권 보호를 검증한다. 사용자의 바탕화면이나 실제 앱은 이 테스트에서 변경하지 않는다. 이 검증은 별도 물리 PC에서의 로그인·앱 사용 및 Windows 알림 클릭 검증을 대신하지 않는다.
