# 전체 로컬 대화를 유지하는 Account Switcher

## 범위

PR #24의 설치 진입점은 이제 `WorkspaceGateway`를 설치한다. 이전 `SessionController`/`DesktopGateway`는 비교·회귀 테스트용으로 남아 있지만 설치되지 않는다.

목표는 **현재 Labels 작업 공간의 CODEX_HOME, 대화 기록, 데이터베이스, 프로젝트, 라벨과 창을 바꾸지 않고 같은 로컬 app-server의 인증만 변경**하는 것이다. 대화 하나를 선택하거나 rollout 파일을 복사하지 않는다. 다른 격리 프로필에 있는 별도 대화를 합치는 기능은 아니다. 별도 CLI로 실행하는 단어장 요약, 원격 호스트 및 다른 앱 프로세스는 이 로컬 app-server 인증 전환 범위에 포함되지 않는다.

로컬 대화는 로그인 계정과 독립적으로 같은 PC 사용자에게 보인다. 이는 대화 데이터의 **계정 간 격리 모드가 아니라 공유 작업 공간 모드**다. 선택한 계정에서 기존 대화를 이어 보내면 그 대화의 기록·코드 문맥이 새 계정으로 전송될 수 있다. UI는 이를 고지하고 명시적 동의 없이는 전환하지 않는다. 계정 전환만으로 전체 대화를 모델에 보내거나 이전 요청을 재실행하지 않는다.

## 전환과 실패 처리

1. 모든 창이 공유하는 로컬 서버의 변경 요청을 잠근다. 진행 중 요청, 응답, 승인, 도구, 명령 및 열린 모든 스레드의 백그라운드 터미널을 확인한다. 현재 선택한 대화만 검사하지 않는다.
2. 서버의 실제 인증 토큰에서 계정·사용자 식별자를 읽어 기존 계정과 비교한다. 이메일 또는 로컬 파일만으로 로그인 성공이라고 판단하지 않는다.
3. 일반 및 보관 대화를 `thread/list`의 모든 페이지에서 조회한다. ID·기록 경로·제목·작업 디렉터리의 집합을 전환 전후 비교한다. 500개에서 자르지 않는다. 반복 커서·불명확한 응답은 성공으로 취급하지 않는다.
4. 인증 변경 전에 `workspace-account.json`에 `pending` 의도를 원자적으로 쓴다. 같은 서버에 `account/login/start`의 `chatgptAuthTokens`를 전달하고 실제 신원 및 `account/rateLimits/read` 성공을 확인한다.
5. 목록 보존과 유휴 상태가 재확인되면 `selected`로 확정하고 이후 요청을 허용한다. 기본 Desktop 목록 응답은 필터·커서·보관 여부를 포함해 수정 없이 통과한다.
6. 실패·취소 시 이전에 검증한 인증을 복원하고 목록을 다시 확인한다. 복원이 불명확하면 작업을 차단한다. 다른 계정으로 모델 요청을 자동 재전송하지 않는다.

토큰·대화 본문은 선택 기록이나 새 renderer API에 저장하지 않는다. Labels 코드가 auth.json/rollout/DB를 복사하거나 덮어쓰지 않는다. 토큰은 등록된 프로필의 기존 인증 파일에서 읽고 app-server의 외부 인증 API에만 전달한다. 갱신 시에도 같은 계정·사용자 신원을 확인한다. 만료된 계정은 기존 계정 관리 경로에서 다시 로그인해야 하며, 다른 계정의 토큰으로 대신하지 않는다.

## 재시작·기본 로그인

재시작하면 같은 CODEX_HOME과 저장된 선택 계정을 재검증한 후 작업 요청을 허용한다. 자격 증명 누락·신원 변경·중단된 전환은 원래 계정으로 자동 복귀하지 않는다. 복구가 막혀 있어도 로컬 대화 목록과 기존 기록 읽기는 허용한다.

Desktop의 기본 로그아웃/로그인도 저장소를 교체하지 않는다. 기본 계정 변경 후에는 Account Switcher에서 문맥 전달에 동의하고 **로그인 확인·복구**를 실행해야 후속 작업을 보낼 수 있다. 로그인 과정이 끝나지 않았거나 작업이 진행 중이면 차단한다. 미동의 상태도 `native-pending`으로 저장하므로 재시작으로 동의 절차를 우회하지 못한다.

이전 실험의 `session-switches/routes.json`에 항목이 남아 있으면 자동 이전하지 않는다. 그 항목은 원본보다 최신인 별도 rollout을 가리킬 수 있다. 해당 실험본에서 필요한 대화를 내보내고 경로별 기록을 대조하기 전에는 파일을 지우거나 덮어쓰지 말아야 한다. 이 후보는 최신 실험 기록을 묵살하고 오래된 원본으로 보내는 것보다 차단을 선택한다.

## 사용 경로

Labels의 **Account Switcher** 버튼 → 대상 계정 선택 → 공유 작업 공간 문맥 전달 동의 → **전체 작업 공간의 계정 전환**.

현재 로그인, 보존되는 로컬 저장소 경로, 전환 시 확인한 대화 수와 차단 상태를 표시한다. 대화별 선택기는 없다. 기존 계정별 창 관리와는 별개의 기능이며, 먼저 관리 경로에서 대상 계정을 등록하고 로그인해야 한다.

## 규약과 지원 조건

- 기존 패키저의 정확한 지원 Desktop 버전 제한을 유지한다.
- 로컬 CLI app-server의 stdio 연결 하나를 가로챈다. CODEX_HOME을 새로 지정하거나 서버를 두 개 만들어 같은 기록에 동시 쓰기하지 않는다.
- 공식 app-server의 외부 인증·목록·사용량 규약을 사용한다: https://developers.openai.com/codex/app-server
- 실제 사용자 ID 검증에는 기존 번들에 있던 `getAuthStatus(includeToken:true)`도 필요하다. 공개 문서의 이메일만으로 대체하지 않는다. 해당 메서드, 외부 토큰 로그인, 보관 목록, 로드된 스레드 상태, 백그라운드 터미널 규약이 다르면 전환을 차단한다.
- 기존 로드된 세션이 실제로 변경된 인증을 사용하는지, Desktop 계정 캐시/알림과 동기화되는지는 반드시 실제 두 계정으로 검증해야 한다. 모의 서버 테스트만으로 이 점을 입증하지 않는다.

## 검증

이번 구현 환경에서 실행한 검사:

```text
node --test tests/workspace-switcher.test.cjs
24 passed, 0 failed

CODEX_LABELS_BROWSER_TESTS=1 CODEX_LABELS_CHROMIUM=/usr/bin/chromium \
  python -m unittest discover -s tests -p test_workspace_switcher_renderer.py -v
5 passed, 0 failed
```

Node 검사는 JSON-lines 스트림 및 임시 파일을 사용하는 **모의 app-server**다. 일반 607개 + 보관 4개 유지, 모든 대화의 후속 요청 계정 변경, 활성 작업/승인/터미널 차단, 신원 불일치, 취소·실패 복원, 커서 반복, 저장 실패, 재시작, 기본 로그아웃/로그인, 오래된 전환 기록 및 IPC 범위를 검사한다. Chromium 검사는 실제 renderer 코드와 모의 IPC로 계정 선택·동의·버튼·실패 표시·구독 해제를 검사한다. 실제 계정이나 모델 요청은 사용하지 않았다.

기존 IPC/단어장 preload 테스트는 노출 순서가 아니라 `codexLabels` 이름으로 API를 선택하도록 수정했다. 새 UI는 기존 CI의 `test_*renderer.py`, Node 검사는 `node --test`에 자동 포함된다. 전체 저장소 CI의 실제 결과는 해당 커밋의 GitHub Actions에서 따로 확인한다.

## Windows 승인 기준 — 아직 미검증

현재 구현 환경에서 사용자 PC 설치·Windows 빌드 실행·실제 두 계정 사용량 귀속은 검증하지 않았다. 이전 PR의 Windows smoke 결과를 이번 구현의 성공으로 간주하면 안 된다. 병합 전에는 백업한 별도 설치 후보에서 다음을 확인한다.

- A 계정으로 여러 프로젝트/대화/라벨/보관 대화를 만들고 목록과 경로를 기록한다.
- 현재 대화 외에 응답 또는 터미널이 실행 중인 경우 전환이 거부되는지 확인한다.
- B로 전환하고 기존 목록·제목·프로젝트·라벨·보관 항목이 보존되는지 확인한다.
- 이미 열린 대화와 아직 열지 않은 대화 양쪽에서 새 요청을 보내 실제 B의 인증·사용량 귀속을 확인한다. 모델 응답만으로 계정 귀속을 추정하지 않는다.
- 앱 재시작 후 B 선택과 전체 목록이 유지되고, B 인증 만료 시 A로 몰래 전송되지 않는지 확인한다.
- 기본 로그아웃/다른 계정 로그인 후에도 목록은 보존되고 동의·신원 재검증을 거쳐 후속 작업이 실행되는지 확인한다.

검증 전에는 Draft를 유지하고 기존 안정 설치본이나 바로가기를 교체하지 않는다.
