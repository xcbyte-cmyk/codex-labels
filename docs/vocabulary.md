# 단어장 — 문맥을 보존하는 개인 용어집

이슈 #8의 기본 구현과 PR #9의 선택 위치 보정을 기반으로 확장한 개발 기능입니다. 소스 또는 PR 생성만으로 설치된 Windows 앱이 변경되지는 않습니다.

## 사용 흐름

답변의 단어 또는 짧은 구절을 드래그한 뒤 선택 툴바의 **단어장**을 누릅니다. 새로운 표현은 현재 Codex 로그인과 `gpt-5.6-luna / xhigh`로 문맥상 뜻, 품사·표현 유형, 짧은 설명, 예문, 태그를 생성합니다. 결과는 미리보기이며 **단어장에 저장**을 눌러야 저장됩니다. **뜻 편집**에서 저장 전 내용을 수정할 수 있습니다.

이미 저장된 표현은 툴바에 **✓ 단어장**으로 표시합니다. 열면 저장된 뜻을 먼저 보여주고 AI를 자동으로 다시 호출하지 않습니다. 저장된 뜻의 문맥과 이번 선택의 문맥이 다를 수 있으므로, 필요한 경우 **새 의미 추가**를 눌러 현재 선택 문맥으로 다시 요약합니다. 기존 뜻은 유지됩니다.

라벨 배지 또는 ＋ 메뉴의 **단어장…**에서 목록을 엽니다. **열기 → 뜻 편집 → 수정 저장**은 AI 호출 없이 기존 항목을 수정합니다. **삭제 → 삭제 확인**은 선택한 의미 한 건만 삭제합니다. 수정한 내용을 버리고 닫거나 다른 항목으로 이동할 때 확인을 받습니다.

## 저장 및 관리

- 항목: 단어·구절, 문맥상 뜻, 품사·표현 유형, 짧은 설명, 예문, 원문 문맥, 출처, 태그, 즐겨찾기, 학습 상태, 모델·추론 강도, 최초 저장·수정 시각.
- 단어·뜻·설명·태그·원문을 검색합니다. 전각 문자, 대소문자, 연속 공백을 정규화합니다. 즐겨찾기와 **미학습 / 복습 필요 / 숙지함** 필터를 지원합니다. 목록은 최근 수정 순입니다.
- 새 의미는 별도 ID로 보관합니다. 동일하게 정규화한 단어와 뜻의 정확한 중복은 거부합니다. 서로 다른 표현의 뜻이 의미상 같은지 AI로 판정하지는 않습니다.
- 편집은 뜻·설명·예문·품사·태그·즐겨찾기·학습 상태만 허용합니다. 원문·출처·식별자·모델 정보는 편집 요청으로 바꾸지 못합니다.
- 출처는 캡처 시 확인 가능한 페이지 제목과 로컬 경로를 저장합니다. 페이지 제목이 대화 제목이라는 보장은 없습니다. 임의 외부 URL, 쿼리 문자열, 상위 경로 이동은 받지 않습니다. **원래 대화로 바로 이동하는 기능은 아직 없습니다.**
- 태그는 최대 5개, 태그당 24자입니다. 자동 태그 역시 미리보기에서 수정할 수 있습니다.

## 로그인과 입력 범위

- 모델 `gpt-5.6-luna`, 추론 강도 `xhigh`를 고정합니다. 다른 모델이나 계정으로 자동 대체하지 않습니다.
- 앱에 포함된 `resources/codex.exe exec`와 현재 `CODEX_HOME`의 파일 기반 ChatGPT 로그인을 사용합니다. 별도 API 키를 요구하지 않습니다. 계정별 홈·저장소 분리는 호스트가 제공해야 하며 계정 창 애드온 자체는 이 변경에 포함하지 않습니다.
- 선택 문자열은 최대 160자, 선택 위치 주변의 문맥은 최대 1,600자입니다. 같은 표현이 문단에 여러 번 나와도 실제 Range 위치를 사용합니다. 여러 인라인 요소에 걸친 구절과 긴 선행 공백도 처리합니다.
- AI에는 **단어와 제한된 문맥만** 전달합니다. 출처 제목·경로와 전체 대화는 전달하지 않습니다. 출처는 로컬 저장용입니다.
- 기존 `--ephemeral`, `--ignore-user-config`, 읽기 전용 sandbox, stdin 전달 및 도구 비활성화 설정을 유지합니다. 사용자 MCP·플러그인·앱·메모리·셸·서브에이전트·웹 검색을 요약에 사용하지 않습니다.
- 창별 동시 요약 1건, 120초 제한입니다. 실패·취소·화면 종료 뒤 늦게 도착한 결과는 저장할 수 없습니다. 저장에 성공한 임시 초안은 소진합니다. 요약 결과의 정확성은 보장하지 않으며 불확실성을 명시하도록 요청합니다.

## 저장 형식과 이전 버전

`vocabulary.json`은 설치 폴더의 라벨 설정과 나란히 보관합니다. 저장 폴더별로 분리되며 대화별 저장소는 아닙니다. 한도는 **의미 항목 2,000개 / 8MB**입니다. 잠금, revision 비교, 임시 파일의 원자적 교체를 유지합니다. 다른 창과 충돌하면 자동으로 덮어쓰지 않습니다.

이 확장판은 파일 형식 **version 2**를 씁니다. 기존 version 1은 읽기만 할 때 변경하지 않습니다. 처음 성공적으로 수정·저장·삭제할 때 원본 바이트를 `vocabulary.json.v1-<SHA256>.bak`으로 백업한 후 version 2로 저장합니다. 백업은 Git에서 제외하며, 기존 백업이 다르거나 손상됐다면 덮어쓰지 않고 오류를 표시합니다.

**같은 저장 폴더를 사용하는 이전 실행본과 새 실행본을 동시에 사용하지 마세요.** 이전 실행본은 version 2를 읽지 못합니다. 롤백 전 모든 창을 종료하고 현재 version 2 파일을 별도로 백업한 뒤 version 1 백업을 복사해야 합니다. 이 경우 마이그레이션 이후 추가한 뜻은 이전 앱에서 사용할 수 없습니다. 구버전 앱으로 돌아간다고 새 데이터가 자동 변환되지는 않습니다.

손상된 파일은 자동 초기화하지 않습니다. 쓰기 중 비정상 종료로 `.lock` 폴더가 남으면 모든 관련 창을 닫고 쓰기 작업이 없는지 확인한 뒤 해당 빈 잠금 폴더만 정리하세요.

## 검증과 배포

```powershell
node --test extension/vocabulary.test.cjs
$env:CODEX_LABELS_BROWSER_TESTS='1'
py -3.13 -m unittest discover -s tests -p test_vocabulary_renderer.py -v
```

`CODEX_LABELS_CHROMIUM`으로 Chromium 경로를, `CODEX_LABELS_VOCABULARY_ARTIFACTS`로 화면 캡처 폴더를 지정할 수 있습니다. UI 검사는 실제 Chromium과 테스트용 IPC·요약 응답을 사용합니다. 실제 Windows Codex 로그인 호출, ASAR 재빌드·설치, 정식 릴리스 검증과는 별개입니다. 전체 저장소 CI와 Windows 실행본 검증 후 배포해야 합니다.

이번 범위에 포함하지 않은 기능은 간격 반복 복습(SRS), Anki 내보내기, 원래 대화로 이동, 기기 간 동기화입니다. 태그·학습 상태는 관리용이며 자동 복습 일정은 만들지 않습니다.

## 모든 대화에서 저장된 단어 표시

같은 단어장 저장 폴더를 사용하는 대화의 일반 본문에서 저장된 단어와 구절을
점선 밑줄로 표시합니다. 저장한 대화뿐 아니라 다른 과거/새 대화를 열었을 때와
스트리밍으로 문장이 추가되었을 때에도 적용합니다. 과거 대화 파일을 일괄 수정하거나
대화 내용을 모델에 보내지 않습니다. 실제로 렌더링되는 본문을 로컬에서 대조합니다.
계정/설치별로 다른 저장 폴더를 쓰면 단어장도 계속 분리됩니다.

밑줄 단어를 클릭하면 저장된 뜻, 품사, 보충 설명, 예문, 태그를 팝오버로 표시합니다.
뜻이 여러 개면 모두 표시하며 현재 문맥에 맞는 뜻이라고 자동 단정하지 않습니다.
각 뜻에서 `단어장 열기`, `수정`, `삭제 → 삭제 확인`을 사용할 수 있습니다.
뜻을 보는 동작은 AI를 호출하지 않습니다. 키보드 사용자는 화면 오른쪽의 `저장된 단어`
버튼 또는 본문에서 `Alt+Shift+V`로 목록을 열고 Tab/Enter로 단어를 선택합니다.
Escape로 닫으면 접근 버튼으로 포커스가 돌아갑니다. 입력창에서는 단축키를 가로채지 않습니다.
표시 개수는 현재 열린 화면에서 검사된 고유 단어 수이며 전체 과거 대화 통계가 아닙니다.

### 매칭과 표시 안전성

- NFKC, 대소문자, 연속 공백을 정규화하되 원래 문자열과 DOM 오프셋을 보존합니다.
  결합 문자, 전각 문자, 인라인 강조에 걸친 구절도 처리합니다.
- 같은 시작 위치에서는 가장 긴 구절이 우선하며 내부 단어를 중복 표시하지 않습니다.
- 단어 경계를 확인합니다. `bank`가 `bankruptcy` 안에서 표시되지 않으며 `run/running`,
  한글 조사/어미 등 형태 변화는 자동 확장하지 않습니다.
- 코드 블록/인라인 코드, 링크, 입력/편집 요소, 버튼, 선택 툴바, 숨겨진 콘텐츠,
  단어장 자체 화면을 제외합니다. 문단이나 링크/코드/줄바꿈 경계를 넘어 구절을 합치지 않습니다.
- CSS Custom Highlight API의 텍스트 범위를 사용합니다. 원문을 innerHTML로 치환하거나
  span으로 래핑하지 않아 원문 노드와 선택 문자열을 유지합니다. 사용자가 드래그하거나
  더블클릭하면 뜻 팝오버를 열지 않고 원래 선택 동작을 유지합니다.
- 해당 API가 없는 실행본에서는 자동 강조만 비활성화하고 단어장은 그대로 열 수 있습니다.
- 본문 탐색 계약은 `[data-selected-text-overlay-target]` 또는 명시적인
  `[data-message-author-role="user|assistant"]`입니다. 다른 앱 버전의 사용자 메시지가
  이 표식을 사용하지 않으면 그 본문에 대한 어댑터 확인이 필요합니다. 사이드바나 화면
  전체를 추측으로 본문 취급하지 않습니다. 실제 Windows Codex의 새 버전 호환성은 미검증입니다.

### 저장 변경 반영과 성능

성공한 저장/편집/삭제는 현재 표시와 팝오버를 갱신합니다. 인증된 같은 저장소의 창에는
`codex-labels:vocabulary-changed` 무내용 신호만 보냅니다. 각 창은 검증된 read IPC로
자기 저장소를 다시 읽습니다. 다른 프로세스가 같은 파일을 원자적으로 교체하는 경우에는
저장 디렉터리의 `vocabulary.json` 변경 감시가 알립니다. 임시 파일/라벨 파일은 무시합니다.
포커스 복귀 시에도 새로 읽으며, 늦게 도착한 이전 읽기 결과가 삭제한 단어를 되살리지 않습니다.
OS 파일 이벤트 누락/권한 오류 또는 프로세스 중단 시에는 즉시 동기화를 보장하지 않습니다.
단어장 새로고침 또는 창 포커스 복귀 후 다시 확인하세요. 별도 계정 저장소에는 전파하지 않습니다.

접두어 인덱스로 찾기 때문에 모든 텍스트를 저장 단어 2,000개마다 재검색하지 않습니다.
새 본문과 변경된 문단을 중심으로 검사하고, 초기에는 화면 인근 600px까지 우선 검사합니다.
화면 밖 문단은 스크롤로 접근할 때 처리합니다. 작업은 문단 사이에서 약 8ms/최대 24단위씩
나누며, 매우 긴 단일 문단 자체의 처리 시간은 이 한도를 넘을 수 있습니다.
페이지 종료 시 관찰자, 이벤트, IPC 구독, 강조 범위를 해제합니다. 다른 기능의 CSS 강조는
제거하지 않습니다. 강조 기능 자체는 저장 파일 형식을 바꾸거나 파일을 쓰지 않습니다.
