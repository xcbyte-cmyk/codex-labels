# Codex Labels 계정 애드온 아이디어

> 작성일: 2026-09-18 · 상태: 검토용 아이디어 / 미구현 설계
>
> 이 문서는 기존 계정별 창 기능을 작은 선택형 애드온으로 정리하기 위한 제안이다. 공통 실행본 전환, 데이터 이전, 배포 또는 기존 실행본 삭제를 수행한 기록이 아니다.

## 1. 제안 요약

**Codex Labels 실행본은 하나만 유지하고, 계정 선택·추가·삭제 기능은 별도 Account Windows 애드온으로 제공한다.**

일반 사용자는 기존 Labels를 실행한다. 여러 ChatGPT 계정을 사용하는 사람만 애드온을 설치해 계정별 작업 창을 연다. 각 창은 공통 실행 파일을 사용하되 로그인·대화·설정·라벨·캐시는 서로 다른 저장소에 보관한다.

기본 앱에는 프로필을 구분해 안전하게 실행하는 최소 공통 기반을 둔다. 계정 관리 화면과 운영 기능은 애드온이 맡는다. 따라서 이 제안은 **작은 공통 기반을 기본 앱의 `main`에 포함하는 것**을 전제로 한다.

## 2. 해결하려는 문제

- 현재 기본 실행본 `app`과 계정 기능용 실행본 `app-accounts`가 함께 있어 실행 파일이 중복된다.
- 두 실행본을 유지하면 Codex 버전 변경에 따른 호환성 확인과 업데이트 대상도 나뉜다.
- 계정 기능이 필요 없는 사용자에게까지 계정 관리 화면을 기본으로 제공할 필요는 없다.
- 잘못 만든 계정을 삭제할 때 로그인 토큰·대화·캐시가 남지 않도록 끝까지 정리해야 한다.

현재도 계정 A와 B가 각각 앱 전체를 복사하는 것은 아니다. 두 계정은 `app-accounts`의 실행 파일 하나를 공유한다. 이번 제안이 줄이려는 중복은 **기본판과 계정 확장판 사이의 실행본 중복**이다.

## 3. 현재 구현과 목표 구조

| 항목 | 현재 구현 | 목표 |
|---|---|---|
| 실행본 | 기본판과 계정 확장판을 별도로 유지 | 공통 실행본 하나 사용 |
| 계정 관리 | 계정 선택용 실행 도구 | 독립적으로 배포하는 애드온 |
| 앱 내부 처리 | 확장 실행본에 계정 초기화·저장소 선택·이름 표시 포함 | 기본 앱의 작은 공통 프로필 실행 기능으로 정리 |
| 계정 데이터 | `app-accounts/accounts/<ID>` | 실행 파일과 독립된 공통 데이터 위치 |
| 삭제 | 대상 프로세스 종료, 폴더 삭제, 잔여 확인, 실패 시 재시도 | 기존 삭제 원칙을 유지하고 새 경로 구조에 적용 |
| 업데이트 | 각 실행본과 도구의 호환성을 확인 | 공통 실행본과 애드온의 호환성을 확인 |

현재 계정 이름은 구분용 별칭이다. 특정 이메일이나 구독의 소유권을 강제하는 기능은 아니다. 두 창에서 같은 ChatGPT 계정으로 로그인하면 같은 구독 할당량을 사용한다.

## 4. 목표 구성

아래는 논의를 위한 예시다. 실제 폴더 이름과 설치 위치는 구현 단계에서 확정한다.

```text
Codex Labels/
├─ app/                         공통 Labels 실행본
├─ addons/
│  └─ account-windows/
│     ├─ addon.json             버전·호환성·실행 진입점
│     ├─ AccountWindows.exe     계정 관리 화면과 실행 도구
│     └─ 문서·라이선스
└─ data/
   └─ accounts/
      ├─ <계정 ID A>/           로그인·대화·설정·캐시
      └─ <계정 ID B>/
```

기본 사용자의 기존 저장소는 그대로 유지하는 것을 우선한다. 위 `data/accounts`는 추가 계정용 위치의 예시이며, 기존 기본 계정의 데이터를 한꺼번에 옮긴다는 뜻은 아니다.

실행 파일을 공유해도 각 계정 창은 별도의 프로세스로 동작한다. 디스크 중복은 줄일 수 있지만, 여러 창을 동시에 실행할 때의 RAM·CPU 소비가 크게 줄어든다고 보장하지 않는다.

## 5. 역할 분담

| 구성 요소 | 책임 |
|---|---|
| 공통 Labels 실행본 | 프로필 ID 검증, 시작 전 저장소 확정, 계정별 라벨 저장소 선택, 창 이름 표시, 같은 프로필의 중복 실행 처리, 잘못된 프로필 실행 차단 |
| Account Windows 애드온 | 계정 목록·추가·실행·삭제 화면, 공통 실행본 탐색, 실행 요청, 선택한 계정의 프로세스 정리, 삭제 결과 확인 |
| 계정 저장소 | 해당 프로필의 로그인·대화·설정·라벨·캐시를 보관. 애드온 프로그램 파일과 분리 |
| 설치·업데이트 도구 | 호환성 검사, 실행 중인 계정 창 확인, 실행 파일 교체, 실패 시 복구, 계정 데이터 보존 |

애드온이 임의의 경로를 주면 앱이 그대로 사용하는 구조는 피한다. 공통 실행본이 지정된 계정 데이터 루트 안에서 유효한 프로필 ID를 찾아 경로를 결정해야 한다.

현재 기본 실행본에 외부 실행 인자만 추가하는 것으로 모든 분리가 유지되는지는 검증되지 않았다. 현재 앱 내부의 계정 처리 코드를 공통 기능으로 정리하는 작업이 필요하다.

## 6. 사용자가 보는 흐름

### 일반 사용

기존 **Codex Labels** 바로가기를 실행한다. 계정 애드온을 설치하지 않아도 기존 사용 방식이 유지된다.

### 계정별 사용

1. **Codex Labels · 계정별 실행**을 연다.
2. 계정 창을 추가하고 구분할 이름을 입력한다.
3. 선택한 창을 열어 사용할 ChatGPT 계정으로 로그인한다.
4. 다른 계정을 선택하면 별도 창이 열린다. 같은 프로필을 다시 선택하면 이미 열린 창으로 연결한다.
5. 창 제목과 상단 표시로 프로필을 구분하고, 실제 로그인 계정은 계정 메뉴에서 확인한다.

초기에는 계정 전용 실행 아이콘 하나로 충분하다. 애드온이 늘어난 뒤 **Codex Labels Add-ons** 통합 실행기를 도입한다. 최초 구현부터 범용 애드온 설치 장터나 통합 관리 시스템까지 만들지는 않는다.

### 사용 중지·애드온 제거·계정 삭제

| 사용자 동작 | 처리 원칙 |
|---|---|
| 계정 기능 사용 중지 | 계정 창을 종료하고 기존 Labels를 사용. 계정 데이터 유지 |
| 애드온 프로그램 제거 | 계정 데이터 보존 여부를 명확히 안내. 애드온 제거만으로 계정 자료를 자동 삭제하지 않음 |
| 선택한 계정 삭제 | 대상 계정의 실행을 종료하고 전용 자료를 실제 삭제. 완료 여부 확인 |

## 7. 계정 분리의 필수 조건

- 계정별로 앱 프로필, `CODEX_HOME`, 필요한 상태 DB 경로와 라벨 저장소를 분리한다.
- 부모 프로세스의 다른 계정 토큰·API 키·실행 서버 주소를 의도 없이 상속하지 않는다.
- 프로필을 지정하지 않은 일반 실행과, 지정한 프로필을 찾지 못한 실패를 구분한다.
- 지정된 프로필이 없거나 손상됐거나 삭제 중이면 실행을 중단한다. 기본 계정으로 대신 실행하지 않는다.
- 로그인 실패나 할당량 제한을 이유로 다른 계정에 작업을 자동 전달하지 않는다.
- 계정 창 별칭만으로 실제 로그인 계정이 확인됐다고 표시하지 않는다.
- 새 구조에서도 A·B 동시 실행과 같은 프로필 재실행을 실제 앱으로 검증한다.

원격 호스트의 작업은 그 호스트의 로그인 상태가 적용될 수 있다. 초기 범위는 로컬 계정 창으로 한정하고, 원격 계정까지 자동으로 고정된다고 안내하지 않는다.

## 8. Codex 업데이트 대응

공식 Codex 업데이트와 Labels가 사용하는 실행본의 교체는 구분한다. 공식 앱이 업데이트됐다는 이유만으로 검증되지 않은 실행본에 애드온을 자동 적용하지 않는다.

제안하는 업데이트 흐름은 다음과 같다.

```text
새 버전 감지
  → 공통 실행본의 지원 버전·연결 기능 확인
  → 애드온 호환성 확인
     ├─ 확인됨: 계정 데이터 유지 → 실행 창 종료 확인 → 업데이트
     └─ 미확인: 애드온 실행 보류 → 업데이트 필요 안내
```

호환성 판단에는 다음 정보를 사용한다.

- 공통 실행본 버전과 기반 Codex 버전
- 프로필 실행 연결 규칙의 버전
- 애드온 버전과 요구하는 연결 규칙
- 실제 검증한 조합

특정 버전 범위 전체를 테스트 없이 호환된다고 선언하지 않는다. `addon.json`의 필드와 버전 규칙은 아직 제안 단계이며, 존재하는 공식 Codex 플러그인 규격을 뜻하지 않는다.

업데이트 중에는 새 계정 실행과 삭제가 충돌하지 않도록 같은 실행본에 대한 잠금을 사용한다. 실패 시 실행 파일을 복구할 수 있어야 하며, 데이터 형식이 바뀌는 업데이트는 이전 버전에서 읽을 수 있는지도 별도로 확인한다.

## 9. 계정 삭제와 잔여 자료 정리

현재 삭제 기능의 원칙을 유지한다.

1. 삭제할 계정 이름과 로컬 자료 삭제 범위를 표시한다.
2. 계정의 신규 실행을 막고, 실제 계정 식별자·저장소 경로로 소유 프로세스를 확인한다.
3. 해당 계정 창과 관련 작업 프로세스를 종료한다.
4. 계정 전용 폴더의 로그인 정보·대화·설정·라벨·브라우저 캐시·플러그인 캐시·진단 파일을 삭제한다.
5. 대상 프로세스와 폴더가 남지 않았는지 확인한다.
6. 마지막 삭제 처리 기록까지 제거한 뒤 완료로 표시한다.

파일 잠금이나 종료 실패가 발생하면 **삭제 미완료**로 남기고 재시도를 제공한다. 목록에서 먼저 없애고 성공처럼 보이게 처리하지 않는다.

계정 삭제 시 백업·휴지통 사본을 만들지 않는다. 다른 계정, 공통 실행 파일, 외부 작업 폴더, ChatGPT 계정·구독 자체는 삭제 대상이 아니다. 여기서 삭제는 로컬 파일시스템 삭제이며 디스크 보안 삭제나 운영체제의 공용 기록 제거를 의미하지 않는다.

## 10. 기존 구조에서 전환하는 순서

### 1단계: 계정 기능의 소스 범위 분리

계정 기능과 다른 기능의 변경을 나눠 별도 작업 폴더에서 관리한다. `codex/account-windows`는 개발 브랜치 이름의 제안이며, 이 문서 작성으로 브랜치를 생성하거나 병합하지 않는다.

### 2단계: 공통 프로필 실행 기능 정의

프로필 ID, 데이터 루트, 실행 중복 처리, 오류 반환, 호환성 확인 규칙을 확정한다. 기본 사용자에게 영향을 주지 않는 경로도 함께 검증한다.

### 3단계: 계정 애드온 분리

기존 계정 선택·추가·삭제 기능을 재사용하고 실행 대상만 검증된 공통 실행본으로 연결한다. 현재 동작을 불필요하게 다시 작성하지 않는다.

### 4단계: 기존 계정 데이터 이전 또는 경로 재연결

계정별 실행을 종료한 상태에서 진행한다. 기존 프로필 ID를 유지하고, 설정 안의 이전 실행본 경로·플러그인 경로·프로필 접근 가능 여부를 확인한다. 새 경로에서 로그인·대화·라벨을 읽고 다시 시작할 수 있어야 완료로 본다.

가능하면 데이터 복사를 줄이고 기존 저장소를 그대로 연결하는 방식부터 검토한다. 위치를 옮겨야 한다면 중단 복구 기록을 두고, 이전·새 위치 중 어느 쪽이 활성 상태인지 명확히 한다. 검증 완료 후 중복 계정 자료가 남지 않도록 정리한다.

### 5단계: 중복 실행본 정리

새 구조의 검증이 끝난 뒤 사용하지 않는 실행 파일만 제거한다. **현재 `app-accounts`에는 계정 데이터도 있으므로 폴더 전체를 먼저 삭제하면 안 된다.**

## 11. 배포·버전 관리

- 기본 Labels와 계정 애드온의 버전은 구분한다.
- 기본 앱에는 공통 프로필 실행 기반만 포함하고, 계정 관리 UI와 삭제 로직은 애드온으로 배포하는 것을 목표로 한다.
- 애드온 패키지에는 관리 도구·메타정보·문서·필요한 라이선스를 포함한다.
- Codex 바이너리나 사용자 `accounts` 자료는 애드온 ZIP에 넣지 않는다.
- 실제 설치된 실행본의 지원 여부를 확인하고, 호환되지 않으면 실행 전에 안내한다.

현재 배포 도구도 Codex 바이너리를 ZIP에 포함하지 않고 PC의 설치본으로 실행 환경을 준비한다. 이번 전환은 다운로드 패키지뿐 아니라 **설치 후 실행본 중복을 줄이는 것**에 의미가 있다.

| 항목 | 기대 효과 또는 한계 |
|---|---|
| 설치 용량 | 기본판·확장판 실행본 중복 감소. 절감량은 전환 전후 실측 |
| 애드온 크기 | 관리 코드와 도구 중심으로 구성. 최종 패키지 크기는 빌드 후 확인 |
| 유지보수 | 공통 실행본의 Codex 호환성 대응을 한곳에서 관리 |
| 선택적 사용 | 필요한 사용자만 계정 관리 기능 설치·실행 |
| 메모리·CPU | 계정별 프로세스가 유지되므로 큰 감소를 약속하지 않음 |
| 업데이트 위험 | 내부 동작이 바뀌면 연결부 수정 필요. 호환성 검사와 실제 실행 검증 필요 |
| 작업 파일 충돌 | 로그인 분리가 같은 프로젝트 파일의 동시 수정까지 막지는 않음 |

## 13. 완료 판단 기준

- [ ] 계정 기능 때문에 별도 Codex/Labels 실행본 전체를 추가로 유지하지 않는다.
- [ ] 애드온 미설치 상태에서도 기본 Labels의 기존 실행과 데이터가 유지된다.
- [ ] 서로 다른 계정 창이 동시에 실행되고 실제 실행 프로세스의 저장소가 분리된다.
- [ ] 같은 프로필을 다시 열면 기존 창에 연결된다.
- [ ] 잘못된 프로필·삭제 중인 프로필·호환되지 않는 조합은 다른 계정으로 전환하지 않고 중단한다.
- [ ] 사용자 로그인 후 실제 사용 계정을 확인한다. 할당량 사용 검증 여부를 별도로 기록한다.
- [ ] 삭제 취소, 정상 삭제, 파일 잠금 실패, 재시도, 다른 계정 보존을 검증한다.
- [ ] 업데이트 성공·실패·복구 과정에서 계정 데이터가 보존된다.
- [ ] 기존 A·B 계정의 전환 후 로그인·대화·라벨·재실행을 확인한다.
- [ ] 전환 완료 후 불필요한 실행본과 중복 데이터가 남지 않는다.

## 14. 구현 전에 결정할 사항

1. **공통 기반의 범위:** 기본 앱에 프로필 실행 연결부를 포함하는 방향을 확정할 것인가?
2. **데이터 위치:** 설치 폴더 하위와 Windows 사용자 데이터 폴더 중 어디를 기준으로 할 것인가?
3. **최초 진입점:** 계정 전용 아이콘으로 시작하고 통합 Add-ons 실행기는 후속으로 둘 것인가?
4. **계정 고정 수준:** 창별 로그인 분리를 유지할 것인가, 특정 실제 계정과의 일치 확인까지 확장할 것인가?
5. **알림·원격 실행:** 초기 제한을 유지하고 별도 기능으로 검증할 것인가?

권장 초기 범위는 **공통 실행본 재사용 + 로컬 계정 창 분리 + 기존 삭제 기능 유지**다. 통합 애드온 관리, 원격 계정 고정, 특정 이메일 강제 연결, 한 창 안의 스레드별 계정 선택은 후속 범위로 둔다.
